**追加した機能のリスクと対策**
- タグのURLが漏れる/コピーされる: URLは HMAC-SHA256 署名(秘密は既存の FORM_SECRET。DBに保存しない)。イベントごとに別、版つきで、主催者が再発行すると古いURLは使えない。付与できるのは、ログイン済み・そのイベントに参加確定の申込がある・開始3時間前〜終了6時間後・OFFでない・未取得の本人だけ。コピーされても、申込のない人や時間外は付かない(家からの不正取得は、時間外・申込なしで拒否)。
- 二重付与: かざした記録の作成(1イベント1人1件)とポイント更新を、同じトランザクションで行う。6件の同時リクエストで1件だけ付くことを実Firestoreで確認。
- 他人のスタンプの閲覧・改ざん: メンバーIDは、セッション(Cookie)からのみ取得し、リクエストの値は使わない。他人のポイントを返す入口はない。実Firestore+実HTTPで確認(他人のチケットにハンコ・情報が出ない)。
- 結果表示用のURLパラメータ(`?tap=`): 案内文と演出にだけ使い、ポイント・ハンコの有無は常にDBで決める(アドレスを書き換えても押されたことにならないことをテスト)。
- 割引: 金額はサーバーで再計算(クライアントの値は使わない)。1人分の申込だけ・二重適用なし・会計確定後と入金超過は拒否。監査ログ(`events/{id}/audit`)に記録。
- 個人データの削除: メンバー削除でスタンプカードとかざした記録を削除。イベント削除でかざした記録(サブコレクション)も削除。
- 状態を変える GET(タグ読み取り)について: NFCタグは GET でしか開けないため、GET で付与する。副作用は「本人の権利のあるスタンプが付く」だけで、冪等。Cookie は SameSite=Lax のため、他サイトからの誘導で付く可能性はあるが、タグのURL(署名)を知らないと実行できず、付くのは本人が受け取れるスタンプのみ。
- 回数制限: タグ読み取りは IP ごとに120回/10分(会場のWi-Fiは同じIPになるため多めに設定。記録に失敗したときは許可。署名が総当たり不能なため)。
- **未確認/残るリスク**: 実機iPhone/AndroidでのNFC読み取り(iPhoneの背景読み取り、ホーム画面アプリとSafariでログイン状態が別になる可能性)、本番URLでの通し確認、QRコード表示は未実装(URLのコピーのみ)、FORM_SECRET を変更するとすべてのタグURLが無効になる。
- **Codexによるレビュー(2026-11-16)と対応**: 8件の指摘のうち7件を修正。(1)【高】割引の回の判定が、別イベントのかざしで変わる → かざし済みのイベントは、そのイベントの記録(`stampTaps.pointsAfter`)で判定。(2)チケットの参加費が受付の請求額とずれる/適用済み割引を二重に引く → 割引前の参加費(`baseFeeYen`)と適用済み額を分けて返し、かざす前は「本日の参加費」・かざした後は「次回の参加費(目安)」と表示。(3)タグの版の確認が付与と別 → 付与のトランザクション内で確認(再発行との競合でも古いURLは通らない)。(5)チケット取得の読み取り量 → 申込の問い合わせを1イベント1回に減らし、90日先まで・60件までに限定。(6)会場Wi-Fiで回数制限に当たる → 120回/10分。(7)メンバー削除でスタンプ記録の削除失敗を握りつぶす → 記録の削除を先に行い、失敗したら削除を中止(再実行できる)。(8)`?tap=__proto__` などで画面が壊れる → 自身のキーだけを許可。
- **修正せず、残るリスクとして記録**: (4)タグのURLを開くだけでスタンプが付く(GETでの状態変更)。NFCタグは GET でしか開けず、「かざすだけで付く」要件のため、確認画面(POST)は入れない。URLが漏れる・保存したURLを遠隔から開く、という不正は、時間枠(開始3時間前〜終了6時間後)・参加確定の申込・1イベント1回で限定される(会場にいなくても、開催中に申込済みの人は付けられる)。厳密に防ぐには、かざすたびに変わる署名つきタグ(NTAG 424 DNA など)が必要で、将来の課題。
- **Codex 再レビュー(2026-11-16)と対応**: 前回の修正を確認し、新たに中3件。すべて修正(再度のCodexレビューは未実施)。(a)割引設定の読み取りに失敗すると既定額で料金を変えてしまう → 料金を変える処理(`applyStampDiscount`)は、設定をトランザクション内で読み、読めない・壊れているときは失敗させる(まだ一度も保存していないときだけ既定値)。(b)同行者がいる申込に、割引後の金額が出る(受付では自動適用されない) → 同行者あり・未適用のときは割引後の金額を出さず「受付で調整します」と案内。(c)メンバー削除と設定変更の同時実行でカードが残る → `setEnabled`/`tap` はメンバーが存在しないと何も作らず、メンバー削除は「記録の削除→メンバー削除→もう一度削除(掃き出し)」の順に行う。テスト: 実Firestoreのスタンプ16件・単体16件成功。**live テストでは未確認**: 設定が壊れているときの拒否(本番の設定を壊すテストは行わない)。

## 2026-11-16 タグを「競技ごとに1枚・毎回同じ」へ変更(ユーザー要望: 「スタンプ扱いなので毎回同じがいい」)
- 変更: イベントごとのタグURLをやめ、競技ごと(バドミントン用・バレーボール用)の1枚にした。URL `/stamp/t/[sport]/[token]`、署名は HMAC(競技+版)、DBは `stampTags/{sport}`(版と履歴)。かざした人が参加確定で申し込んでいる開催中のイベントを探して付与する。付与の条件(ログイン・参加確定の申込・開始3時間前〜終了6時間後・ON・1イベント1回)と、付与のトランザクション内での版の確認は変わらない。まだイベントごとのURLをタグに書き込んでいない段階での変更のため、移行は不要。
- **リスクの変化(受け入れた上で記録)**: 以前は、URLが漏れても、そのイベントの開催時間帯(最長でもその前後)にしか使えなかった。今回は、タグ(URL・QR)が毎回同じため、漏れたURLは再発行するまで、**すべての開催の時間帯**で使える。ただし付与の条件は変わらないので、URLを知っていても、申込のない人や時間外には付かない。残る不正は、「申込済みの人が、会場にいなくても、開催時間中にURLを開いてスタンプを付ける」こと(URLが漏れた場合)。対策: URLを他人に見せない、QRは開催時間中だけ掲示する、漏れたら再発行する。厳密に防ぐには、かざすたびに変わる署名つきタグ(NTAG 424 DNA など)が必要で、将来の課題。
- 競技ごとに署名が別のため、バドミントンのタグでバレーボールのスタンプは付かない(テストで確認)。
- **Codex レビュー(2026-11-16・タグ変更分)と対応**: 中2件・低1件。すべて対応(再レビューは未実施)。(a)申込の読み取りに失敗すると、早いイベントを飛ばして後のイベントへ付与する → 読み取り失敗は握りつぶさず失敗させ、ポイントは付けず「もう一度かざしてください」(`tap=retry`)を出す。(b)検索範囲外(開始15日以上先・終了4日以上前)の申込を early/late でなく noreg にする → 範囲は仕様(開始14日先まで・終了3日前まで)として明記し、案内文を「いま開催中の、参加確定の申込がありません」にして、境界外のテストを追加。(c)タップごとの問い合わせ数に上限がない → いまに近い順に30件まで(開催中のものは、いまに最も近いので落ちない)。回数制限に当たったときは `tap=busy`。
